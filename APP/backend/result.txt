## منهجية التصنيف

- `EXPLICIT`: موجود مباشرة في implementation أو schema أو migration أو test.
- `INFERRED`: استنتاج قوي من أكثر من implementation، لكنه ليس تصريحًا مستقلًا.

## 1. Executive Architecture Summary

`EXPLICIT`: المشروع Backend مبني على Fastify 5 + TypeScript CommonJS + Prisma 7 + PostgreSQL عبر `@prisma/adapter-pg`. التحقق والـserialization يستخدمان Zod 4 عبر `fastify-type-provider-zod`، وOpenAPI يولد من schemas routes.

`EXPLICIT`: المعمارية الفعلية هي modular/domain-oriented مع طبقات عملية غير مفروضة كـinterfaces عامة:

```text
HTTP Request
  -> Fastify instance / global onRequest
  -> access-level encapsulation: public | user | admin | external
  -> authentication hook عند الحاجة
  -> Zod validation
  -> permission أو API-scope preHandler
  -> route handler
  -> module service
  -> Prisma client / أحيانًا raw SQL advisory lock
  -> response envelope + Zod serialization
  -> centralized audit onResponse عند انطباقه
```

`EXPLICIT`: لا توجد Controller classes أو Repository layer عامة مستقلة. معظم handlers تنشئ service وتستدعيها مباشرة؛ services تحتوي business logic وPrisma queries. توجد helpers وطبقة DB مشتركة (`transaction`, `advisory-lock`, `idempotency`, `prisma-error`, `outbox`) لكنها ليست repository abstraction موحدة.

`EXPLICIT`: النظام ليس generic auth template فقط؛ يحتوي domain فعليًا على master data، customers/vehicles/purchase experiences، complaints، call center، communication templates، imports، reports، integrations وexternal API.

`INFERRED`: أفضل mental model لإضافة Diamond Rent Car هو الحفاظ على module domain بنفس convention، مع جعل route contract وpermission وservice وPrisma model جزءًا من feature boundary.

## 6. Authentication Architecture

### التقنية

`EXPLICIT`: combination من:

- Short-lived signed JWT access token.
- Opaque random refresh token مخزن hash فقط في `AuthSession`.
- Opaque password reset/account setup/2FA challenge tokens في `SecurityToken`.
- TOTP 2FA وrecovery codes.
- External API keys منفصلة عن user JWT.
- Cookie support موجود للـaccess token، لكن login response أيضًا يعيد token pair.

### Login flow

```text
POST /auth/login
 -> authRateLimit + Zod LoginSchema
 -> normalize email
 -> user lookup with passwordHash omission override
 -> reject missing user/hash أو suspended
 -> Argon2id verify
 -> إذا 2FA enabled: create opaque challenge فقط
 -> غير ذلك: create AuthSession + opaque refresh token
 -> sign JWT access token
 -> return { data: result }
```

`EXPLICIT`: login لا ينشئ session أو access token قبل نجاح factor الثاني عند تفعيل 2FA.

### JWT

- Library: `@fastify/jwt`.
- Secret: `JWT_ACCESS_SECRET`.
- Payload الفعلي: `{ sub: userId, sid: sessionId, type: "access" }`.
- TTL: `ACCESS_TOKEN_TTL`, default 900 seconds.
- لا توجد permissions داخل JWT.
- لا يوجد issuer/audience configured في plugin المفحوص. `UNKNOWN`: هل هناك reverse proxy أو outer layer يفرضهما.
- يمكن التحقق من access token من Authorization Bearer عبر fastify-jwt، وcookie `access_token` configured.

### Refresh

`EXPLICIT`: `POST /auth/refresh` يستقبل `{ refreshToken }`. القيمة raw random base64url، تخزن SHA-256 hash فقط، session تحمل `familyId`, expiry, revokedAt, rotatedAt, IP وuser-agent.

Rotation تستخدم conditional `updateMany` كـcompare-and-set. token المعاد استخدامه أو المنتهي يلغي sessions غير الملغاة في نفس family. replacement يبقى في نفس family. TTL الافتراضي 30 يومًا.

`HIGH/INFO`: `JWT_REFRESH_SECRET` مطلوب في env لكنه غير مستخدم لأن refresh ليس JWT. هذا configuration debt ويمكن أن يضلل المشغل.

### Logout

`POST /auth/logout`: يأخذ `sessionId` من request.auth وuser ID، ويضع `revokedAt` للـsession الحالية فقط. إذا لم يوجد sessionId لا يفعل شيئًا. لا يوجد blacklist access JWT؛ access token يبقى صالحًا حتى expiry، بينما refresh session تلغى.

### Password reset/setup

- `POST /auth/password-reset-request`: لا يكشف وجود الحساب خارجيًا.
- token opaque/hash-only، scope `PASSWORD_RESET`, expiry من env.
- `POST /auth/password-reset-confirm`: يتحقق scope/expiry/usedAt، ثم transaction يستهلك token، يضع Argon2id hash، يفعل user، ويلغي sessions.
- `POST /auth/account-setup`: نفس pattern مع `ACCOUNT_SETUP`.
- عند email disabled في non-production قد يسجل reset link raw للتجربة المحلية. `MEDIUM`: هذا مقبول محليًا لكنه يتطلب حماية logs والالتزام بعدم تفعيل هذا المسار في production.
- admin reset: `POST /users/:id/reset-password`، permission منفصلة، transaction hash + session revocation.
- `UNKNOWN`: لا يوجد self-service change-current-password endpoint مستقل في routes المفحوصة.

### 2FA

`EXPLICIT`: TOTP RFC 6238-compatible: SHA-1، 6 digits، 30 seconds، window ±1. secret 160-bit مشفر AES-256-GCM بالمفتاح `TWO_FACTOR_ENCRYPTION_KEY`.

Setup: pending encrypted secret -> verify code -> promote active -> generate recovery codes. replay guard عبر `twoFactorLastUsedStep`. recovery codes hash-only and single-use conditional update. Login challenge opaque scope `TWO_FACTOR_CHALLENGE` مع expiry وmaximum attempts. لا تصدر session قبل verify/recovery.

2FA management routes authenticated، account ID دائمًا من `request.auth.id`; disable/regenerate يتطلبان password + second factor، ويلغيان sessions الأخرى. 

## 7. Login / Token / Refresh / Logout Flows

### Access token request

كل route تحت `routes/user` أو `routes/admin` يدخل `preValidation`:

1. `request.jwtVerify()`.
2. expired -> `TOKEN_EXPIRED`/401.
3. invalid -> `TOKEN_INVALID`/401.
4. database lookup user بواسطة `sub` مع roles/permissions الحالية.
5. missing -> unauthorized.
6. `SUSPENDED` -> `ACCOUNT_SUSPENDED`.
7. `PENDING` -> `ACCOUNT_SETUP_REQUIRED`.
8. بناء `request.auth`.
9. best-effort throttled `lastSeenAt`.

### Account states

`PENDING`: setup مطلوب ولا login عادي.
`ACTIVE`: يسمح بالمصادقة.
`SUSPENDED`: يمنع login/new authenticated requests؛ users service يسحب sessions عند suspension حسب implementation المرتبط بالstatus path.
`DELETED`, `UNVERIFIED`: غير موجودة كـUserStatus enum.

### Session end

`EXPLICIT`: session تنتهي بالexpiry، logout، password reset/admin reset، refresh reuse detection، أو suspension behavior. access JWT نفسه ليس stateful blacklist.

## 8. Authorization Architecture

### User RBAC

```text
User
  -> UserRole
      -> Role
          -> RolePermission
              -> Permission.key
  -> request.auth.permissions
  -> route schema.permissions
  -> hasAnyPermission
  -> handler/service
```

`EXPLICIT`: permission list تقرأ من DB في كل authenticated request؛ لذلك تغيير role/permission ينعكس دون إعادة إصدار JWT. semantics للroute metadata هي ANY-of: يكفي وجود permission واحدة من القائمة.

route بلا `permissions` داخل user/admin ليس public؛ هو authenticated-only.

### External authorization

```text
API key header
  -> verify prefix/hash/revocation/expiry
  -> request.apiAuth
  -> schema.apiScopes
  -> ALL scopes required
  -> external service
```

API keys لها scopes وbranch scope. creation يقيد authority الممنوحة بسلطة المنشئ.

### Ownership and scoping

`EXPLICIT` توجد ownership/scoping service rules، وليست global Fastify guard عامة:

- notifications user routes تستعلم userId الحالي فقط.
- 2FA user routes تستخدم current auth id فقط.
- complaints/customers/call center/reports تستخدم branch/department visibility permissions وquery filters في services.
- `view_all_branches` و`view_all_departments` permissions تتجاوز scoping في domains المحددة.
- user branch assignments قد تشتق من department assignments.
- لا يوجد multi-tenant isolation عام؛ `KNOWN-LIMITATIONS.md` يصرح بذلك.

`UNKNOWN`: لا يمكن إثبات أن كل resource-level path في كل domain متسق بدون مراجعة سطرية لكل service/query؛ tests تغطي أجزاء منها.

## 11. Database Architecture

`EXPLICIT`: PostgreSQL + Prisma 7 + `PrismaPg` driver adapter. Connection من `DATABASE_URL`. Prisma Client يتصل أثناء plugin registration، وdisconnect أثناء close.

Global omission:

- `User.passwordHash`, active/pending 2FA encrypted secrets.
- `AuthSession.refreshTokenHash`.
- `SecurityToken.tokenHash`.
- `TwoFactorRecoveryCode.codeHash`.

`EXPLICIT`: transactions عبر `withTransaction`، advisory locks PostgreSQL عبر `pg_advisory_xact_lock`، idempotency create-first عبر `IdempotencyKey`، وoutbox durable event tables. الاستعمال ليس repository-mediated؛ services تستدعي Prisma مباشرة أو helpers.

`EXPLICIT`: migration system Prisma، migration الحالية `20260903000000_init` هي initial schema الظاهرة. التاريخ التفصيلي قبلها غير موجود في repository؛ `UNKNOWN`.

## 16. Security Model

### Controls present

- Argon2id password hashing.
- short-lived JWT access token.
- opaque hashed rotating refresh token + family reuse detection.
- global Prisma secret omission.
- AES-256-GCM for TOTP/integration secrets.
- opaque/hash-only reset/setup/challenge/recovery materials.
- global + auth rate limits.
- CORS env allow-list، wildcard rejected in production.
- Helmet، though CSP disabled.
- multipart size/file count/field count limits.
- magic-byte upload verification، server-generated storage key، traversal check.
- structured Pino redaction for auth headers/cookies/passwords/tokens/secrets.
- no stack returned to clients.
- permission metadata automatic enforcement.
- branch/department/resource scope in services.
- idempotency/advisory locks/transactional outbox patterns.

### Findings

**HIGH: `trustProxy: true` without repository-visible proxy boundary.**

`src/app.ts` trusts forwarded request metadata. IP drives rate limit/audit and can affect security telemetry. If deployment proxy does not sanitize forwarded headers, client can spoof source information. Proxy configuration is `UNKNOWN`; deployment must constrain trusted proxy or sanitize headers.

**MEDIUM: rate limiting is in-memory/per-instance.**

Global, auth and API-key buckets do not coordinate between replicas. A horizontally scaled deployment gets a multiplied limit and weaker brute-force protection. This is explicitly documented in `KNOWN-LIMITATIONS.md`.

**MEDIUM: scheduler is in-process.**

`SCHEDULER_ENABLED=true` starts cycles in every listening replica. Code uses idempotency/advisory locks, which reduces duplicate work, but timer HA/throughput/ownership remains deployment-sensitive. Documentation itself says dedicated distributed runner/leader election is needed for scale.

**MEDIUM: audit is best-effort.**

`audit.onResponse` writes after response and catches failures. Security-sensitive operations can succeed while their audit row is absent. For mandatory audit operations the row should be part of the business transaction, but this is an observation only, not a change.

**MEDIUM: email delivery is best-effort/no durable retry for generic mailer.**

Mailer returns status and notifications can be skipped. Complaint delivery has a durable model, but generic account email is not a queue-backed provider in the inspected implementation.

**LOW/MEDIUM: CSP disabled.**

Helmet is enabled but CSP intentionally disabled for JSON API/Swagger. This is reasonable for an API, but responsibility shifts to frontend/reverse proxy.

**LOW: unused `JWT_REFRESH_SECRET`.**

Required secret implies JWT refresh design while implementation uses opaque refresh tokens. It increases operational secret surface and can create false assumptions.

**INFO: no multi-tenancy.**

No tenant/org isolation is implemented. Branch/department scopes are operational filters, not tenant boundaries.

**INFO: no Redis/cache/queue/realtime.**

No Redis, BullMQ, WebSockets or distributed broker. In-app notifications are DB-polled.

### Security items not evidenced

- CSRF strategy: `UNKNOWN`. Cookie support exists and credentials are enabled; sameSite lax helps but no explicit CSRF token mechanism was found.
- WAF/reverse proxy/TLS termination: `UNKNOWN`.
- secret rotation process: `UNKNOWN`.
- database encryption/backups/least-privilege DB user: `UNKNOWN`.
- external penetration test: `UNKNOWN`.

## 21. Module Development Pattern

الـpattern الفعلي/المعلن:

```text
src/modules/<feature>/
  <feature>.schema.ts
  <feature>.service.ts
  [domain helpers/config/errors]
  routes/
    public/route.ts
    user/route.ts
    admin/route.ts
    external/.../route.ts
```

خطوات إضافة module جديد:

1. حدد model/schema contract.
2. أضف Prisma schema file إذا احتاج domain persistence.
3. شغل `npm run db:generate` ثم migration حسب environment.
4. أنشئ Zod input/output schemas وresponse envelope.
5. أضف permissions إلى `src/constants/permissions.ts`، فتدخل seed catalog.
6. أنشئ service للbusiness logic وPrisma access.
7. ضع route تحت access-level الصحيح.
8. في protected route أضف `permissions`; في public route ضعها تحت `routes/public` و`public: true`.
9. استخدم `withTransaction` للmulti-write، advisory lock للمنافسة، `runIdempotent` للآثار الخارجية.
10. استخدم `request.setAudit` للتغييرات الحساسة.
11. أضف locale keys EN/AR عند وجود نص user-facing.
12. أضف unit/integration security tests وOpenAPI check.
13. شغل quality gates.

`EXPLICIT`: route handler يجب أن validate/delegate/return؛ business logic في service. `INFERRED`: repository منفصل ليس invariant؛ لا ينبغي اختراعه إلا إذا أضيف باتساق مع module complexity.

## 22. Request Lifecycle

```text
HTTP request
  -> Fastify router / request id
  -> global onRequest: resolve language
  -> global rate limit / CORS / Helmet / parsers بحسب plugin
  -> route encapsulation selected by path folder
       public: no auth hook
       user/admin: preValidation JWT + DB identity
       external: onRequest API key + usage limiter
  -> Zod validation (body/query/params)
  -> preHandler permission ANY أو API scope ALL
  -> route handler
  -> service business logic
  -> Prisma transaction/query/advisory lock/idempotency/outbox as needed
  -> Zod response serialization/envelope
  -> onResponse audit and/or API usage log
  -> client
```

ملاحظة ordering مهمة: user authentication قبل schema validation عمدًا حتى anonymous malformed request يحصل على 401 بدل كشف schema بـ422. public routes لا تتأثر.

## 23. Authentication Mental Model

```text
User submits email/password
  -> normalize + DB lookup
  -> Argon2id verify
  -> optional TOTP challenge
  -> AuthSession row with hashed opaque refresh token
  -> signed short-lived JWT {sub, sid, type}

Next request
  -> JWT verify
  -> DB reload current User + Roles + Permissions
  -> request.auth
  -> route metadata permission check
```

- المستخدم identity هو DB User، وليس claims كاملة.
- ما يخزن بعد login: AuthSession row؛ raw refresh token يعود للclient ولا يخزن raw.
- request recognition من JWT `sub/sid` ثم DB.
- Role يحدد عبر UserRole/Role.
- Permissions يعاد تحميلها من RolePermission/Permission كل request.
- المنع عند auth `preValidation` أو permission `preHandler`.
- تعطيل user عبر status `SUSPENDED`، ويمنع login/requests الجديدة، مع session revocation حسب service.
- logout revokes current refresh session فقط.
- session تنتهي expiry/revoke/reuse detection/password reset/suspension paths؛ access token لا يلغى server-side قبل expiry بشكل عام.

## 24. Authorization Mental Model

```text
User
  -> UserRole
  -> Role
  -> RolePermission
  -> Permission keys
  -> request.auth.permissions
  -> route schema.permissions
  -> enforcePermissions preHandler (ANY)
  -> service resource/branch/department checks
  -> business logic
```

مثال request: `GET /complaints/:id`:

1. autoload يضع route في admin scope.
2. admin hook يضيف JWT `preValidation`.
3. token `sub` يتحقق، user/roles/permissions تقرأ من DB، `request.auth` يبنى.
4. Zod يتحقق من numeric id.
5. preHandler يقرأ `permissions: [complaints.read]`; missing -> 403.
6. complaints service يحمّل complaint ويطبق branch/department visibility بحسب caller permissions/assignments.
7. mapper يعيد `data` schema-safe.
8. audit لا يسجل GET تلقائيًا إلا لو explicit action.

External example يمر بدل ذلك بـAPI key `onRequest`, `apiScopes` ALL، ثم external service وusage log.

- Identity/system: users, roles, permissions, sessions, security tokens, audits, idempotency.
- Organization: branches/departments and user assignments.
- Operational: customer has many purchase experiences; vehicles/models and branch/salesperson connect to experiences.

## 26. Architecture Invariants

`EXPLICIT` invariants extracted from code/docs:

1. Backend is authority for auth, authorization, validation.
2. Public access is folder-explicit; absence of permission never means public.
3. Protected routes declare metadata permissions; no forgotten manual guard.
4. Permission checks use stable permission keys, not localized messages or role names.
5. Passwords only Argon2id hashes; raw passwords never logged/returned.
6. Secret/token hashes and 2FA secrets are globally omitted from Prisma results.
7. Multi-row/multi-table writes use transaction.
8. Concurrency-sensitive operations use advisory lock/CAS/unique constraints.
9. External side effects use idempotency where required.
10. User-facing text uses i18n; clients branch on stable error codes.
11. Responses use `{ data, meta? }`; errors use structured envelope.
12. Every route should have Zod summary/operationId/tags/inputs/response.
13. Sensitive mutations call `request.setAudit`.
14. Files use server-generated storage keys and content/magic-byte validation.
15. Master/reference entities prefer soft deactivation and preserve history.
16. No fake provider connected status; integrations report real configuration.
17. No tenant isolation should be assumed from branch scope.
18. Add modules under domain folder and access-level route folder so autoload applies correct hook.

## 27. Risks & Technical Debt

### High priority

- Trusted proxy boundary is not represented in repository (`trustProxy: true`). Validate production proxy sanitization and trusted-hop configuration.
- Route-level permission completeness requires ongoing review: centralized enforcement is strong, but an authenticated-only route with no `permissions` is intentional only if ownership/auth-only semantics are correct. This is a review risk, not proven bypass.

### Medium priority

- Per-instance in-memory rate limiting is unsuitable as the sole control with multiple replicas.
- In-process scheduler can run in every replica; locks/idempotency mitigate duplicates but not distributed worker architecture concerns.
- Best-effort audit means successful sensitive operation can lack audit row.
- Generic email is best-effort and disabled by default without durable retry.
- `JWT_REFRESH_SECRET` is mandatory but unused; configuration/documentation mismatch.
- `runIdempotent` reserves before effect but does not show a recovery state if the process crashes after reservation and before effect completion; suitability depends on caller/effect semantics.
- Local disk file storage does not provide object-storage durability or multi-instance shared files.

### Low/Info

- CSP disabled intentionally; frontend/proxy responsibility must be explicit.
- No generic cache; every authenticated request reloads permissions from DB.
- No tenant model, queue broker, Redis or realtime channel.
- Generated Prisma Zod file is excluded from typecheck/lint by design; generated artifact integrity relies on `db:generate`.
- Docs mention Node 20+; exact production Node image/process manager is `UNKNOWN`.

### Potential inconsistencies to monitor

- `src/constants/permissions.ts` includes product permissions even though CLAUDE describes template plus operational core; this is intentional in current repository but Diamond Rent Car should decide whether to extend or replace domain catalog.
- `docs/engineering-standards/KNOWN-LIMITATIONS.md` contains a section saying 2FA is intentionally not included, while current implementation clearly includes TOTP/2FA. This is documentation drift and should be corrected before using docs as sole authority.
- README says `npm test` unit tests/no DB while script includes integration files; integration tests may self-skip, but wording is not exact.

## Final Conclusion

هذا Backend Template فعلي modular وليس skeleton فارغًا. أقوى contract لديه هو: Fastify access-level autoload + Zod route contracts + automatic metadata RBAC + Prisma global secret omission + service-owned business logic + transaction/CAS/advisory-lock/idempotency patterns.

عند بناء Diamond Rent Car، المسار الأقل مخاطرة هو إضافة domain modules تحت `src/modules` بنفس route access-level convention، إضافة Prisma schema في ملف domain مستقل، تعريف permissions/catalog/seed، وضع business rules في service، وتغطية branch/department/ownership authorization في service/query لا في frontend. يجب التعامل مع rate limiting الموزع، scheduler، audit atomicity، local storage، proxy trust وغياب tenant isolation كقرارات deployment/architecture صريحة، لا كميزات موجودة ضمن template تلقائيًا.
